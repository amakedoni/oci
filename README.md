# Лабораторная работа 2

**Вариант 4. Управление процессами и обмен данными через каналы.**

Македонский Александр Сергеевич, группа М8О-210БВ-25.

Программа написана на C11 с использованием POSIX API для Linux. Родитель передаёт символы команд через первый канал дочерней программе. Потомок читает строки с помощью `getline`, последовательно делит первое число на остальные и записывает результат в файл. Нулевой делитель проверяется в потомке и завершает оба процесса.

Через второй канал потомок отправляет `A` — готовность принять следующую строку или `Z` — остановку из-за нулевого делителя. Первый `A` отправляется после открытия файла. После каждой строки родитель ждёт ответ; следующая команда после `Z` не передаётся. Пустая или неверная строка не записывается в файл, после неё можно продолжать ввод.

## Сборка и запуск

Нужны C-компилятор и Make. Команды выполняются из корня репозитория:

```sh
make -C src
./src/build/parent
```

Путь к потомку по умолчанию — `./src/build/child` относительно текущей папки. При запуске из другой папки нужно явно передать путь: `/путь/к/oci/src/build/parent /путь/к/oci/src/build/child`.

Первая строка ввода — имя выходного файла. Существующий файл перезаписывается. Затем вводятся строки чисел с десятичной точкой. Для завершения ввода используется Ctrl-D.

```text
result.txt
100 2 5
7.5 2.5
-24 2 -3
```

Файл `result.txt` будет содержать числа `10`, `3` и `4`, каждое с новой строки. Пустые строки пропускаются; строки с некорректными числами отклоняются с диагностикой. Сообщения с PID выводятся на русском в stderr. При системной ошибке печатаются русское пояснение и номер ошибки ОС; текст не зависит от языка системы.

Готовые примеры:

```sh
./src/build/parent < src/examples/normal.in
cat src/build/results.txt
./src/build/parent < src/examples/zero.in
```

Во втором примере код завершения равен `2`, а в `src/build/zero-result.txt` остаётся только `6`: команда после нулевого делителя не выполняется.

## Проверки

Для тестов нужен Python 3 без дополнительных пакетов.

```sh
make -C src test
make -C src sanitize
```

Проверяются вычисления, ошибочный ввод, длинные строки, обрыв каналов, системные ошибки и завершение процессов. Из 17 тестов на macOS проходят 16; один тест `/dev/full` пропущен, поскольку устройство отсутствует. Обычная сборка, AddressSanitizer, UndefinedBehaviorSanitizer и статический анализ Clang ошибок в выполненных проверках не выявили. Логи сохранены в `report/logs/`. Запуск в Linux и трассировка strace в этих логах не представлены.

## Демонстрация через strace

На Linux с установленным strace:

```sh
make -C src
strace -f -o src/build/trace.log ./src/build/parent < src/examples/zero.in
echo $?
cat src/build/zero-result.txt
```

Ожидаются код `2` и число `6` в выходном файле. `-f` включает наблюдение за потомком, `-o` сохраняет журнал. strace запускается снаружи программы; в исходниках показаны системные вызовы, которые он отслеживает.

| В журнале | Место в исходниках |
| --- | --- |
| `pipe` или `pipe2`, `fork` или `clone` | `src/parent.c`, строки 50–52 |
| `dup2`, `execve` | `src/parent.c`, строки 55–60 |
| `open` или `openat`, запись результата | `src/child.c`, строки 43 и 72 |
| Ожидание событий `poll` | `src/parent.c`, строка 79 |
| Чтение и запись байтов | `src/common.c`, строки 30 и 38 |
| Ответ `write(1, "Z", 1)` | `src/child.c`, строка 64; `src/common.c`, строка 38 |
| `wait4` или `waitpid` | `src/common.c`, строка 68, вызов `waitpid` |

Имена библиотечных функций и вызовов ядра могут отличаться. `getline` видна в трассе как чтение через `read`, а `dprintf` — как запись через `write`. Родитель передаёт команды по одному байту: это упрощает код, но увеличивает число системных вызовов на длинных строках. Потомок использует один автоматически растущий буфер `getline`, который освобождается при завершении. Фактическая Linux-трасса в сохранённых логах отсутствует.

## Состав

- `src/parent.c` — создание потомка и обмен командами.
- `src/child.c` — чтение строк, разбор чисел, деление и запись результатов.
- `src/common.c`, `src/common.h` — передача байтов, сигналы, закрытие дескрипторов и ожидание потомка.
- `src/Makefile`, `src/tests/`, `src/examples/` — сборка, тесты и примеры.
- [Отчёт PDF](report/report.pdf) и [редактируемый отчёт DOCX](report/report.docx).

Очистка файлов сборки: `make -C src clean`.
